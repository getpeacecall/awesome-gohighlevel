# Contribution Guidelines

Thank you for your interest in contributing to **awesome-gohighlevel**! This list aims to be the most comprehensive, high-quality collection of GoHighLevel resources available.

## Adding a Resource

Please ensure your pull request adheres to the following guidelines:

### General

- Search previous suggestions before making a new one to avoid duplicates.
- Make an individual pull request for each suggestion.
- Use the following format: `- [Name](link) — Short description.`
- Use an em dash (`—`) between the name/link and description, not a hyphen.
- Keep descriptions concise — ideally one line.
- Descriptions should start with a capital letter and end with a full stop.
- Check your spelling and grammar (Australian English preferred).
- New categories or improvements to the existing categorisation are welcome.

### Quality Standards

- The resource must be directly related to GoHighLevel.
- The link must be working and accessible.
- For GitHub repositories:
  - The repository should have a clear README.
  - The project should be maintained (no abandoned projects with critical open issues).
  - The repository should have at least a basic description.
- For tools and integrations:
  - They should be functional and usable.
  - Commercial tools are acceptable but must be clearly marked.
- For tutorials, videos, and courses:
  - Content should be up to date (or clearly marked with the date).
  - Content should be accurate and well-produced.

### Pull Request Process

1. Fork this repository.
2. Create a new branch: `git checkout -b add-resource-name`.
3. Add your resource to the appropriate section in `README.md`.
4. Ensure the list is alphabetically sorted within each section.
5. Commit your changes: `git commit -m 'Add resource-name to section'`.
6. Push to your branch: `git push origin add-resource-name`.
7. Open a pull request using the [PR template](.github/pull_request_template.md).

### What We Do Not Accept

- Self-promotional content without genuine value to the community.
- Resources behind paywalls without clear indication.
- Broken or dead links.
- Duplicate entries.
- Resources unrelated to GoHighLevel.

## Updating Your Pull Request

If your pull request is not accepted straight away, the maintainers may ask you to make changes. There is no need to open a new PR — just update the existing one.

## Reporting Issues

If you find a broken link or an outdated resource, please open an issue so we can fix it.
